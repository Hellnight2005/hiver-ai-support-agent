🛡️ Deterministic Escalation Safety

The policy engine deterministically enforces safety thresholds, preventing hallucinations and policy violations:

  • Intent Confidence Threshold: Minimum 0.80 required to auto-handle.
  • Evidence Similarity Threshold: Minimum 0.75 cosine similarity to auto-handle.
  • Sensitive Category Filter: Fraud, legal threats, and security always escalate.
  • Deterministic Diagnosis: Explicit, human-readable reason provided for every decision.

🔒 Zero Data Leakage Architecture

Strict graph isolation eliminates train-test contamination across multi-turn reply trees:

  • Partitioning Unit: Splitting strictly performed at Conversation ID level (not row-level).
  • Retrieval Index Exclusion: Evaluated query IDs are explicitly excluded from nearest-neighbor search.
  • Automated CI Verification: Automated check passes with 0 overlapping conversation IDs.

Empirical Failure Mode Taxonomy

Derived by scripts/analyze_failures.py from the 200 golden evaluation records.

Failure Mode #1: Unnecessary Escalation

163 cases (93.7%)

Root Cause: Sparse retrieval index (8 sample dev conversations). Cosine similarity fell below the 0.75 threshold, triggering conservative safe escalation.

Customer: "My package was supposed to arrive yesterday but hasn't arrived"
Expected: AUTO_HANDLE
Actual: ESCALATE (Retrieval confidence low)

Remediation: Full Kaggle dataset index (~108K conversations) provides high-density matches to unlock auto-handling.

Failure Mode #2: General Misclassification

11 cases (6.3%)

Root Cause: Boundary confusion on overlapping keywords (e.g. "billed for gift card" triggered refund instead of fraud).

Customer: "I was billed for a gift card that I never purchased or authorized."
Expected: Intent: account_security
Actual: Intent: refund_request

Remediation: Fine-tune embeddings with hard-negative contrastive loss on fraud vs billing keywords.
